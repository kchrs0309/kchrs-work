Summary:
SAA - pass the app marker on the e/m-commerce capture

Description (paste into Jira text/markup editor):

*CARD*
 * *as* EPI Issuer hub
 * *i want to* pass the standalone-app marker on the E/M-Commerce capture via the PHPR_ZUSATZDATEN_ANLEGEN and ONLINEUEBERW_SEPA_EINREICH dyns services
 * *so that* core banking and the fraud check can tell a Wero Standalone App payment apart from a banking-app payment

*CONVERSATION*
 * Description:
 ** Implement the standalone-app marker on the E/M-Commerce capture as described on the [Consumer PSP API] E/M-Commerce - Request payment capture page; the changed steps are 14, 17 and 19.
 ** The wallet-type origin attribute that drives the marker is delivered by EPI-8728.

*CONFIRMATION*
 * When PHPR_ZUSATZDATEN_ANLEGEN is called for a capture whose wallet type is the Standalone App, field 3 (Software Identifier) is sent with the standalone value; for the banking app the existing value is sent unchanged.
 * When ONLINEUEBERW_SEPA_EINREICH is called for a capture whose wallet type is the Standalone App, the AUSLOESEKANAL parameter is sent with the E/M-Commerce LA-key.
 * Field 69 (INDICATOR_FOR_EM_COMMERCE_TRANSACTION) is sent with value "002" unchanged for both apps.

*NOTES*
 * Fachspez:
 ** The capture provides additional information to the core banking system, including which wallet type the payment approval was given on.
 * Open Questions:
 ** The concrete E/M-Commerce LA-key value for the AUSLOESEKANAL parameter is still to be defined.
 ** The standalone value for the Software Identifier field is still to be defined.
